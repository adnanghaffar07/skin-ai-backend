# Database design proposal

**Date:** 2026-10-28  
**Status:** Applied to Supabase project `skin-ai` (`awhulfitatettoqllejm`, eu-west-1) on 2026-10-28. The SQL lives in `supabase/migrations/`. Prisma is not connected yet because the database password stays in a local `.env`.  
**Engine:** PostgreSQL on Supabase, Prisma from Nest.  
**Source:** Figma Design page `30:6`, scoped to onboarding and the skin dashboard.

## Rules

- UUID primary keys generated by the database.
- Timestamps are `timestamptz` in UTC.
- Money is `numeric(12,2)` plus ISO `currency_code`.
- Questionnaire labels live in rows. Status values the API freezes are Postgres enums.
- JSONB is limited to the submission snapshot and later provider payloads.
- Face bytes are not a column. `scan_images.object_key` points at private R2.
- Self-reported answers, Skin-preference exclusions, and AI observations are different tables.
- The mobile client has no table access. Nest uses a server role and checks the JWT owner. RLS stays enabled with no privileges for `anon` or `authenticated`.
- Cart, orders, wishlist, payment, and dermatologist booking are not in this migration.

## Questionnaire

### `onboarding_sessions`

`user_id` is nullable until Sign up claims the session.

| Column | Type |
|---|---|
| `id` | uuid PK |
| `user_id` | uuid FK nullable |

| `status` | enum `active`, `completed`, `abandoned` |

### `questionnaire_definitions`

`id`, `key` (`onboarding`), `version`, `status` (`draft`, `active`, `retired`), `locale`, `title`. Unique `(key, version)`. One active row per key.

### `questionnaire_questions`

`id`, `definition_id`, `key`, `position`, `prompt`, `help_text`, `selection_mode` (`single`, `multi`), `required`, `min_selections`, `max_selections`.

Unique `(definition_id, key)` and `(definition_id, position)`.

### `questionnaire_options`

`id`, `question_id`, `code`, `label`, `position`. Unique `(question_id, code)`.

## Scans

### `scan_sessions`

| Column | Notes |
|---|---|
| `id` | uuid PK |
| `user_id` | FK, required. Anonymous submit is rejected |
| `submission_id` | FK nullable |
| `consent_id` | FK to a live `facial_image_processing` grant |
| `status` | See below |
| `idempotency_key` | Unique with `user_id` |
| `failure_code` | Later |
| `submitted_at` | When the signed-in user confirms the photo |
| timestamps, `deleted_at` | |

Status: `awaiting_upload`, `uploaded`, `ready_for_analysis`, `queued`, `processing`, `completed`, `retake_required`, `failed`, `cancelled`.

This contract writes `awaiting_upload`, `uploaded`, `ready_for_analysis`, and `cancelled`. The later values exist so a future analysis phase does not need an enum change. Nothing in this contract inserts a row because the Reading-your-skin screen was shown.

Index `(user_id, created_at desc)` where `deleted_at` is null.

### `scan_images`

`id`, `scan_id` unique, `storage_provider` (`r2`), `bucket`, `object_key`, `content_type`, `byte_size`, `checksum_sha256`, `width`, `height`, `created_at`, `deleted_at`.

Object key: `scans/{user_id}/{scan_id}/{image_id}.jpg`.

## Assessments, empty in this contract

### `skin_assessments`

`id`, `scan_id` unique, `user_id`, `status` (`validated`, `rejected`), `summary`, `limitations` text[], `schema_version`, `model_version`, `prompt_version`, `created_at`.

### `assessment_observations`

`id`, `assessment_id`, `feature_code`, `intensity`, `location_note`, `score` smallint nullable, `confidence` numeric(4,3), `evidence` (`model_observed`).

Feature codes used by Home, Your scan, and Progress: `hydration`, `texture`, `redness`, `fine_lines`. Skin report also reads `uneven_tone`. Unique `(assessment_id, feature_code)`.

`score` is the 0–100 value Home shows for hydration and texture. It stays null until a validated assessment exists.

### `progress_entries`

`id`, `user_id`, `scan_id` unique, `captured_on`, `overall_score` smallint nullable, `created_at`.

Progress comparison and “what changed” sentences are not columns of free text in this contract. They are derived later from two observation rows. The table only reserves the score so Home’s “last 4 scans” has a place to read.

## Catalog

### `brands`

`id`, `name`, `slug` unique. Sample on product details: Glow Skin.

### `product_categories`

PK `code`. Seed from Question 9 and the routine steps: `cleansers`, `moisturizers`, `serums`, `sunscreens`, `exfoliants`. Display names match the question labels.

### `products`

`id`, `brand_id`, `category_code`, `slug` unique, `name`, `description`, `benefits`, `how_to_use`, `suitable_for`, `cautions`, `status` (`draft`, `active`, `archived`), timestamps, `deleted_at`.

Product details sections Key Benefits, How to use, Suitable for, and Cautions & Warnings map to those text columns. Sample name: Hydrating Face Serum.

### `product_media`

`id`, `product_id`, `url`, `alt_text`, `position`. Public catalog images, not the face bucket.

### `product_market_availability`

PK `(product_id, market_code)`, `badge_code`, `is_available`. Your scan shows a US badge on the earlier sample card.

### `product_variants`

`id`, `product_id`, `sku` unique, `name`, `status`. One default variant per product so prices have a parent. The screens have no variant picker.

### `product_prices`

`id`, `variant_id`, `market_code`, `currency_code`, `amount`, `compare_at_amount`, `effective_from`, `effective_to`.

Sample on product details: amount `34.00`, compare-at `40.00`, currency `USD`. Index `(variant_id, market_code, effective_from desc)`.

### `product_rating_snapshots`

`product_id`, `rating_avg` numeric(2,1), `rating_count`, `captured_at`. Sample 4.5 and 1,069 reviews. Mark seed rows as sample data.

### `ingredients`, `ingredient_restrictions`, `product_ingredients`

`ingredients`: `id`, `inci_name` unique, `display_name`, `slug`.  
`ingredient_restrictions`: `ingredient_id`, `restriction_code` (`fragrance`, `retinol`, `essential_oils`), `severity` (`exclude`).  
`product_ingredients`: PK `(product_id, ingredient_id)`, `position`.

## Recommendations and routines

### `recommendation_sets`

`id`, `user_id`, `scan_id` nullable, `submission_id`, `basis` (`self_reported`, `assessed`), `rule_version`, `market_code`, `created_at`.

This contract writes `self_reported` only.

### `recommendation_items`

`id`, `recommendation_set_id`, `product_id`, `variant_id`, `rank`, `currency_code`, `amount`, `reason_codes` text[], `explanation` nullable.

`explanation` stays null. Reason codes are machine codes.

### `skincare_routines`

`id`, `user_id`, `recommendation_set_id`, `version`, `status` (`active`, `replaced`), `routine_date`, `created_at`.

### `skincare_routine_steps`

`id`, `routine_id`, `period` (`morning`, `evening`), `position`, `product_id`, `step_type` (`cleanse`, `treat`, `nourish`, `moisturise`), `title`, `amount_label`, `duration_label`, `instruction`.

The routine frame’s “1 min”, “2 drops”, and “Two finger lengths” are `duration_label` or `amount_label` copied from the template at build time.

### `routine_step_completions`

`id`, `step_id`, `user_id`, `completed_on` date, `completed_at`. Unique `(step_id, completed_on)`.

**Mark as complete** inserts a row for the current date. Home and Routine compute `completed_count` from this table.

## Indexes and deletes

- Partial unique index on `questionnaire_definitions (key)` where `status = 'active'`.
- One draft submission per onboarding session.
- Unique `(user_id, idempotency_key)` on scans where the key is not null.
- `pg_trgm` on `products.name` when the extension is available; otherwise `ILIKE` until then.
- Catalog FKs used by recommendations: `ON DELETE RESTRICT`.
- Answers under a submission: `ON DELETE CASCADE`.

## Retention

| Data | Proposal |
|---|---|
| Face objects | Delete on request. Otherwise 24 months after `submitted_at` |
| Scan metadata after image delete | Keep status and timestamps, set `deleted_at` |
| Answers and preferences | Life of the account |
| Anonymous drafts | 14 days |
| Audit events | 24 months, without direct identifiers after account deletion |
| Provider payloads | 90 days once that phase exists, then null the JSON |

| Actor | Access |

| Admin | Catalog and knowledge documents. Not other customers’ face images |
